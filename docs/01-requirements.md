# 01 · 需求与成功标准

## 用户与业务目标

面向查询制度或产品信息的员工。输入问题和可选对话历史，得到可核验的原文证据；资料不够、存在冲突或工具不可用时，明确说明缺口，避免员工依据编造或过时的唯一结论行动。

所选题号：**3 · 企业知识问答 Agent**。使用五份小型合成文档，涵盖报销、年假、产品字幕及账号问题。所有内容只用于演示，与小影真实资料无关。

## 输入、输出和范围

输入为 JSON：`question` 是必填非空字符串，最多 2000 字；`history` 可省略，最多 10 条 `user`/`assistant` 消息，每条最多 2000 字。历史只用于理解追问，不能作为制度依据。空问题是输入错误；“那个呢？”等缺主题的问题由模型请求澄清。

每份资料有文档 ID、版本日期和短原文片段。输出包含 `answer`、`citations`（文档/片段 ID、日期、范围、原文）、`conflicts`、`gaps`、`follow_up_question`、`status` 和运行元数据。

本次完成 CLI、两类本地资料工具、真实 DeepSeek 模型适配器、有界工具循环、离线替身、自动测试与 Trace。未实现网页、在线发布、权限系统、向量库、生产级 Runtime 或多 Agent，均非题目必需。

## 验收映射

| 验收点 | 成功标准 | 复现用例 |
|---|---|---|
| 明确答案 | 先检索、再读原文，答案引用正确 ID 和版本；引用支持事实 | `01-clear` |
| 文档冲突 | 读取 D01/D02，列出 30/15 天，查证后无法确定则追问；不能按日期擅自选一方 | `02-conflict` |
| 资料外问题 | 改写查询后仍无资料，说明缺口，不用模型常识编写公司政策 | `03-out-of-domain` |
| 改写后的相似问题 | 口语表达仍检索到 D03，证据与正常问题一致 | `04-paraphrase` |
| 上下文追问 | 根据历史理解“那”，重新读取 D03，返回提前 3 个工作日申请 | `05-context-follow-up` |
| 工具失败 | 观察失败后决定再试或停止；不把失败标成成功；保留此前已读原文 | `06-transient-tool-failure`、`07-persistent-tool-failure` |
| 信息不足 | 请求具体主题，输出缺口及明确追问 | `08-missing-topic` |
| 有界执行 | 模型决策/工具调用上限耗尽时返回 `limit_reached`，不虚报已回答 | `09-step-limit` 及工具上限单测 |
| 数据变化 | 10 改为 12 天后答案变化；消除文档差异后不再请求冲突确认 | `10-document-mutation`、`11-conflict-removed` |
| 可复现交付 | 同仓库保存输入、实际输出、Trace、测试和五份必需文档；无真实密钥 | README 与 `examples/` |

实际记录分别见 [离线汇总](../examples/mock/summary.md)与[DeepSeek 真实验收](../examples/live/summary.md)。真实正常、冲突、无资料、上下文、工具错误等路径均已执行；[复核说明](../examples/live/review.md)保留首轮断言误判及重评边界。
